調査方法

このサイトの数字は、上流リポジトリの追跡・契約監査・baseline 記録の3つで支えています。すべて再実行できます。

1. 追跡（track_upstream）

毎日 21:00 UTC に scripts/track_upstream.py が main の新しい commit を取得し、ランキングに関係するファイルが変わっていれば GitHub issue を起票します（.github/workflows/track-upstream.yml）。

  • 監視対象: home-mixer/、vm-ranker/、xai-value-model/、phoenix/、candidate-pipeline/、simclusters/ など。
  • 2026-09-24 の値モデル抽出で vm-ranker/ と xai-value-model/ へ実装が移ったため、この2つを監視対象に追加しました。
  • 変更は「ranking（スコア）」「policy（ポリシー）」「unrelated」に分類し、回帰用の corpus（37ケース）で精度を検証しています。

2. 契約監査（audit_model_contract）

scripts/audit_model_contract.py が上流ファイルを GitHub の raw エンドポイントから取得し、重み・設定・数式を解析して、記録済みの baseline と比較します。

世代読み取るファイル使う期間
source_2026_10vm-ranker/params.rs、xai-value-model/scoring.rs、xai-value-model/weights.rs、home-mixer/scorers/value_model.rs2026-09-24 以降
source_2026_08home-mixer/params/param.rs、home-mixer/scorers/ranking_scorer.rs2026-08-13 〜 2026-09-23
  • 重み: param! マクロの既定値を解析（例: ClickWeight … 0.3）。
  • 数式: offset_score の3分岐、unoffset_score の逆変換、normalization の対象 action を文字列で検証。
  • モデル: Phoenix の MODEL_CFGS から4 profile の寸法を抽出。
  • 差分が0なら UNCHANGED、あれば --fail-on-drift が終了コード1を返します。

3. 記録（baseline と preset）

ファイル内容
state/model_contract_baseline.json基準 commit 時点の重み・設定・数式・model profile・action space
weights.jsonプリセット（upstream_2026_10 / 09 / 08 ほか）と設定
docs/upstream-2026-*.md変更の取り込み receipt（issue 番号との対応表）
state/upstream_tracking_corpus.json追跡の分類を検証する37ケース

再現

python scripts/audit_model_contract.py --ref main --json --fail-on-drift
python -m xalgo.cli score <URL> --preset upstream_2026_10 --json
